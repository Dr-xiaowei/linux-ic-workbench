# 0.6.0-rc1 Linux Agent 验证报告

2026-09-26。Linux Agent 已实现并完成程序与 CentOS 执行验证；**小模型的复杂自主规划未通过，不能等同于公司模型验收完成**。使用与工程适用性见 [完整说明](LINUX_AGENT.md)。公司 EDA 本轮未执行。

## 已通过

- 宿主完整 Go race：67 个顶层测试通过，无跳过；包含原有平台功能和 10 个新增 Linux Agent 测试。`go vet`、JavaScript 语法检查通过。
- 实际 QEMU CentOS 6.9 / Linux 2.6.32 x86_64：65 项通过、2 项跳过，原因是该最小虚机没有 clang/Verible；这两项已在宿主真实工具下通过，不能当作目标 Linux 编译器验收。
- 两个真实普通 UID 503/504 的生产浏览器：6 组通过。确认前不执行、授权发送后重置、分别写入本人文件、读取对方私有文件被 OS 拒绝、交叉令牌 401、非零退出码、刷新回执恢复、stdout 运行中显示、停止命令及中英文窄屏。模型为确定性合同服务，执行和文件权限为真实 Linux，不把合同服务当成 AI 智能证据。
- 文件哈希冲突、新文件排他发布、软链接/范围限制、命令超时和进程组取消、输出上限、凭据环境过滤/跨 stdout 分段遮蔽、24 次工具预算、任务落盘和重启中断。普通 JSON 文本绝不自动执行，无调用时明确未执行。
- 网页 Demo 可打开；隔离数据上的模拟 Agent 和十页导航通过。用户原 Demo `state.json` 与 `workspace.json.gz` 在更新前后哈希一致，没有生成独立 Demo 包。

## 真实小模型观察

模型、QEMU 和工具复用此前下载且验证来源的本地文件，本轮未下载新模型、Agent 框架或系统依赖。推理在宿主执行，工具在真实 CentOS 中以普通 UID 运行。

1. Qwen2.5-Coder 1.5B 输出工具请求的普通 JSON 文本，没有原生 `tool_calls`，因此未执行。发现后新增明确的“未执行”反馈和针对性回归；保留发现问题时的原始记录。
2. Qwen3 0.6B 在早期字符串参数格式中出现字段遗漏、JSON 换行转义错误。改进为原生 JSON 对象参数，并兼容原有客户端，新增严格字段检查测试。
3. 最终对象格式下，Qwen3 成功调用系统查询并返回真实 Linux/UID，但多步“创建文件→读取”任务仍给出不支持的绝对路径、遗漏内容/哈希，重复错误参数，最后模型请求达到超时。平台拒绝这些参数，任务显示失败，未伪造文件或命令成功。这证明失败可见，不证明小模型已胜任自主研发任务。

最终多步失败证据为 `validation/linux-agent-rc1/real-model.json`；另有只读命令补验：模型实际执行了 `pwd`，返回真实目录与退出码 0，但遗漏要求中的 `id -u`，因此任务整体验收仍未通过。证据见 `real-model-command.json`。这验证了真实模型→工具→Linux→回执链路，不能据此声称任务完成率达标。 公司 GLM 5.3 的工具协议、规划质量、上下文上限及真实工程任务还需要现场验收。

## 交付、继承与限制

交付为 0.6.0-rc1 Linux x86_64 生产候选和更新后的网页 Demo。Go 1.23.12、静态链接、GOAMD64=v1；Schema 6 / 草稿 Schema 1 不变，保留已有项目路径、备注、软件/模型配置和草稿。安装与数据保留的独立证据见本目录 `validation/linux-agent-rc1/upgrade.json`，包文件摘要另列于 release 校验清单。

当前命令以账号原权限执行，工作目录不是沙箱；自主模式按轮授权。文件工具冲突检查不能替代外部编辑器/NFS 的事务锁；Shell 写入不具备该保护。默认命令 60 秒、最多 300 秒，整轮 10 分钟/24 次调用/12 轮；输出 64 KiB，最近终端回执持久保存。完整语义详见使用说明。

公司 GLM、Virtuoso/ADE/Spectre、PDK/许可证、真实 GPU、公司 NFS/ACL、多节点调度和长时间多人负载未现场验证。此前 rc3 的磁盘写满、异常退出、并发配置/安装、端口及多 UID 故障记录继续保留，不能称为本次全部重跑。没有修改全局 `.cshrc`、复制项目备份或清理原个人数据。

QEMU、两个小模型、工具与虚拟磁盘仍保留；验证服务完成后停止释放资源，只有网页 Demo 继续提供预览。环境文件清理必须等待用户确认。
