# Linux Agent 与模拟 IC 工程适用性评估

2026-09-26 · 0.6.0-rc1。新增能力已经实现；具体实测结果见 [本轮报告](LINUX_AGENT_REPORT.md)。本页的“后续建议”不等于已经开发或已经得到用户确认。

## 使用方法

1. 在终端运行 `~/.local/bin/ic-workbench`，使用打印的网址及令牌打开页面。升级方法仍见 [部署说明](DEPLOYMENT.md)。
2. 在设置页配置内网模型并启用工具调用。模型必须兼容 Chat Completions 的 `tools` / `tool_calls`，普通文本回复不能代替工具调用。
3. 在 AI 对话中选择项目或文件夹，再选择 Linux Agent 的本轮模式。通用会话使用设置中的工作目录；未设置时使用当前账号的 HOME，执行记录显示实际目录。
4. 描述目标。可让 Agent 查询系统、检查文件、生成脚本、执行测试、根据实际错误修正文件并复验。阶段、工具参数、最近一次命令、实时输出、PID、退出码均在当前页显示。停止按钮取消当前推理或命令。

| 模式 | 行为 |
| --- | --- |
| 关闭终端操作，默认 | 保留普通问答和原有平台工具，不提供 Linux 工具；模型自行要求执行也会被拒绝 |
| 本轮逐项确认 | 系统信息和文本读取直接执行；命令、创建目录、写文件先显示参数，确认后才执行 |
| 本轮自主执行 | 允许模型在本轮连续执行 Linux 工具并根据回执继续处理；发送后选择器归回关闭，下轮需要重新选择 |

“允许平台数据修改”是原有项目/配置等操作的开关；它不代替 Linux 模式的授权。EDA 页继续使用该连接允许的 MCP 工具，不会获得本轮 Linux 授权。网页 Demo 的 Linux 操作全部是明确标记的模拟，不运行主机命令。

可尝试：

> 检查当前目录和 Linux 系统版本，列出一级文件，说明有哪些可用的脚本。只读，不修改。

> 在当前项目下创建 `agent_notes`，生成一段 Python 2.6 兼容的 CSV 指标检查脚本。运行它检查我指定的 CSV，报告行数、错误和退出码；失败时先读取错误再修正，不改原始 CSV。

> 读取 `check_results.py`，说明问题，修改后用 `python -m py_compile check_results.py` 验证。不要安装依赖，不访问公网。

## 执行边界和资源

- 命令通过非交互 `/bin/bash -c` 执行，使用当前账号和加载过的工作环境。支持多行命令，但不提供交互 SSH、密码输入或 GUI 鼠标操作；拒绝以 root 身份运行命令。
- **工作目录不是系统沙箱。** Shell 保留账号原有文件、网络和程序权限。提示词中的约束不是操作系统安全策略；本轮自主授权应视为把该账号的终端操作交给模型。过滤模型密钥环境变量和已知凭据输出，只减少意外暴露，不能阻止同 UID 命令主动读取其他文件、父进程环境或使用已有提权能力。
- 文件工具限制为选定目录中的相对路径，拒绝软链接及常见凭据目录，单文件 UTF-8 文本最多 120 KB。新文件以排他发布方式防止覆盖，修改文件须提供先前读取的 SHA256；临时文件同步后原子替换，冲突报错。此检查串行化本服务的文件工具，但不是跨外部编辑器/NFS 的事务锁。Shell 编辑不受此哈希保护。
- 命令默认 60 秒，最多 300 秒；整轮最多 10 分钟、24 次工具调用、12 轮推理。沿用全局工作进程并发上限。超时和停止会终止命令进程组；普通后台子进程不留存。主动脱离进程组的程序、系统崩溃后的残留进程不在完整作业调度保证之内，长仿真应使用 EDA/任务接口。
- 命令输出最多 64 KiB，达到上限明确提示；页面约 1.2 秒拉取进度，隐藏时暂停。平台记录事件最多约 96 条，每条限制 4 KB，不为项目生成备份副本。完整的最近一次终端回执保存在该会话 LastTask；更早命令只有截断的工具记录/消息摘要，不宣称不可篡改的全量审计。
- 先落盘操作意图再调用工具。中途无法保存记录时停止后续操作；服务器正常重启后从本地恢复最近回执，未完成任务显示中断，不自动重跑。硬崩溃时最后未落盘的 stdout 可能丢失。每个 UID 使用独立平台数据库、配置和令牌；用户有意共同编辑一个共享项目时，仍需遵守公司文件权限和协作流程。

## 方案调研与选择

选择 **B：延用现有 Go Agent / 进程 / 存储框架，参考成熟 Agent 的工具—执行—观察循环**。无需新增常驻服务、Python 包、Docker 或模型下载，不更换 CentOS 6.9 运行栈。本轮只参考官方文档与接口设计，没有下载或复制第三方 Agent 源码。

| 候选 | 十项适配检查的结论 |
| --- | --- |
| A，直接采用 OpenHands SDK/Agent Server | 维护：官方现有仓库；许可：MIT；功能：终端/编辑/任务工具；接口：Python/TypeScript/REST；模型：需另测本公司端点；运行：独立现代运行栈；旧系统：未证明 CentOS 6.9 可运行；资源：本机未测；数据：需要接入既有隔离存储；成本：重写现有集成，当前不采用 |
| B，在现有 Go Agent 增加 Linux 工具 | 维护：本项目负责；许可：无新依赖；功能：满足本次非交互 Linux 操作；接口：延用现有模型工具接口；模型：合同服务和小模型分层验收；运行：原静态 Go 二进制；旧系统：实际 QEMU 验证；资源：输出/任务预算有界；数据：复用 Schema 6、UID 隔离；成本：增量实现，采用 |
| C，另写全新 Agent/容器调度器 | 维护、许可、接口和测试都要重新建立；同样要重做模型兼容、旧内核支持、资源治理、数据迁移和集成；对本轮收益不足，不采用 |

[OpenHands 官方 SDK](https://github.com/OpenHands/software-agent-sdk) 给出终端、文件编辑和任务跟踪工具及本地/隔离工作空间两类运行方式；本项目只借鉴工具闭环，未获得其隔离能力。[旧 OpenHands CLI](https://github.com/OpenHands/OpenHands-CLI) 的当前 README 明确停止活跃维护，因此不把旧 CLI 当成新依赖。维护情况为本次查看时的信息，未审计其全部提交或安全性。

[Aider 的 lint/test 工作流](https://aider.chat/docs/usage/lint-test.html) 支持修改后由检查器反馈；适合继续强化本项目已有的 Code 检查/修复能力。它不是模拟电路电气正确性的证明。[Skillbridge](https://unihd-cag.github.io/skillbridge/) 提供 Python 与 Virtuoso SKILL 的桥接设计，可作为后续实际 Virtuoso 会话接入的候选；其公司版本、许可和部署方式仍需评估。[AiiDA 工作流](https://aiida.readthedocs.io/projects/aiida-core/en/stable/topics/workflows/usage.html) 可参考依赖组织、恢复和来源记录；不建议为当前轻量客户端直接引入其整套服务。

## 对模拟 IC 公司的实际评价

**目前适合作为工程师个人研发助手和小范围试点候选，尚不能替代公司成熟的模拟设计验证平台或承担签核结论。** 管理和通用自动化已经具备价值，真正的模拟研发提效还取决于真实 PDK、ADE/Spectre、公司模型和调度系统的接通质量。

| 工作 | 当前能力与实际限制 |
| --- | --- |
| 日常资料/工具管理 | 项目路径、备注、标签、文件查看搜索、独立软件环境、多语言和持久化可用；不会替代设计数据库的并发锁/版本管理 |
| 脚本和代码工作 | 已有导入、AI 修改候选、检查器反馈、审阅与导出；新增 Agent 可执行脚本并读取退出码；必须区分语法正确与电路正确 |
| 日志、表格、波形分析 | 通用文本/CSV/VCD 可用，AI 可就地解释；专有 PSF/FSDB、大规模结果、混合单位/复杂工况尚需厂商导出和性能验收 |
| 模拟电路设计闭环 | 有 EDA/MCP 接口与参数优化后端，但未在真实公司 Virtuoso/ADE/Spectre 和 PDK 中验收；不把模拟器启动成功当成指标达标 |
| 数字与版图工程 | 通用代码/报告、软件环境和 MCP 架构可复用；DC/VCS/Calibre 等每种版本的命令、授权、数据库和签核流程仍需单独适配 |
| 公司级可靠性 | 已有不同 UID 的私有记录、端口/令牌隔离、升级保留和故障测试；未证明公司 NFS/ACL、许可证队列、多台计算节点或大规模多人共享协作的完整可靠性 |

## 后续建议与验收顺序

以下是优先级建议；尚未确认的新功能不自动实施。已确认过的自动调参、结果证据等需求继续保留，项目文件页仍保持纯文件管理。

1. **先完成一个真实模拟设计闭环。** 选择运放、Bandgap 或 LDO 中一个脱敏测试项目：读取 ADE 设置 → 明确版本/工艺角/电压/温度 → 发起 Spectre → 导出指标 → 同基准比较。工程师手工结果作为标准，验收运行可复现、失败可定位、结论有证据。Virtuoso 会话桥接可比较现有 OCEAN/SKILL 适配与 Skillbridge，不先堆更多厂商名称。
2. **建立“指标与工况”规范。** 把 DC 工作点、增益、GBW、相位裕度、噪声、功耗等定义、单位、测量窗口、corner/PVT、Monte Carlo seed、通过条件一同记录。AI 引用具体测量和日志行；无法确定时标成假设。规范能直接服务已经确认的自动调参，防止模型优化错目标。
3. **让 Agent 修改更可审查、执行更可控。** 在已经存在的 Code 候选审阅上扩展多文件差异预览、公司命令策略和任务权限范围，优先限定有边界的脚本工作流；需要时在现代服务器上部署隔离执行端。多文件 Git/diff 对应仍待确认的 IDEA-11，不默认为已开发。现有自主终端不等同于这些能力。
4. **接入公司的许可证和任务队列。** 根据实际使用的 LSF/Slurm/其他队列提供适配，分别显示等待许可、排队、运行、失败和指标不合格；支持中断恢复、资源预算、同一任务身份的取消。不要让网页重试重复启动昂贵仿真。
5. **建立内部知识与模型验收集。** 用经过授权的设计规范、工具手册、历史 debug 案例回答并附来源；预先定义几十个脱敏任务，分别评估普通问答、工具选择、修改成功率、错误恢复和“错误宣称完成”次数。小模型只验证接口和基础闭环，不能推断 GLM 5.3 已达到工程水平。

建议先做第 1 项的一条链路，并同步落实第 2 项的最小指标规范；用人工耗时、Agent 总耗时、返工次数和错误结论率比较两种方式。通过后再扩大到 PVT/Monte Carlo、优化和公司多人试用。这样能直接检验研发收益，而不是用页面数量评价平台成熟度。
