# EDA 任务对话与代码检查闭环

适用 0.5.0-rc2 / 主数据 Schema 6。网页 Demo 与 Linux 候选包使用同一界面，继续隔离配置和数据。IDEA-09、IDEA-10 已由用户确认并实施；全量 LSP、工程符号导航、多文件 Git 修改集不在本次实现中。

## 项目登记与本地记录

项目只登记路径、备注、说明、标签和逐文件注释，不复制工程目录。公司负责工程备份。平台已移除手动备份按钮与 Agent 动作，旧 `/api/backup` 请求返回错误，不再生成备份包；旧备份文件保留。格式迁移时仅保留一次原始 `state.json` 恢复文件，以满足升级不丢数据，不包含项目文件副本。

模型/软件/MCP/插件配置、会话、执行回执和 Code/分析/计算器草稿继续在用户本地数据目录保存。沿用已有路径即可升级。主记录 64 MiB、未压缩草稿 12 MiB 上限保持不变，草稿仍使用 gzip，超限不覆盖已存数据。详见 [本地数据](LOCAL_DATA_AND_CODE.md)。

## 用对话控制 EDA

1. 在“设置与验证”配置内网模型 URL、模型名与密钥环境变量，并启用模型工具调用。模型必须支持兼容 Chat Completions 的 `tools` / `tool_calls`；不支持时返回真实错误，不切换外部模型。
2. 在 EDA 控制左侧选择内置 Cadence 桥接，或添加 stdio / Streamable HTTP MCP 服务。外部连接的“允许工具”填服务实际提供的工具名；先“连接并获取工具”核对 schema。接入细节见 [EDA MCP](EDA_MCP.md)。
3. 在“AI 任务对话”输入项目/输入文件、具体动作与目标，点击“执行任务”。此次任务只获得当前连接白名单中的工具及 schema，不获得其他连接或通用平台操作。缺少必要信息时模型应在原页澄清。
4. 原页显示连接、规划轮次、工具调用、队列/执行状态、服务端进度通知、工具回执与最终答复。外部服务不提供进度通知时显示实际阶段，不伪造完成百分比。内置仿真会继续跟踪后台 job 到完成；外部后台任务需 MCP 本身提供状态工具，模型再调用查询。
5. “停止任务”取消模型请求和当前 MCP 请求；符合协议的服务会收到取消。外部服务已脱离请求创建的后台作业不一定终止，需要其取消工具。不要把请求停止理解为厂商进程已关闭。

每个 MCP 连接有自己的对话和未发送草稿，与普通 AI 对话分开。最新任务的进度和最终回执落盘，刷新可恢复；服务重启后未完成任务标记为 `interrupted`，不会自动重复执行厂商动作。操作历史仍可读取此前工具回执。

资源界限：同一会话一次任务；最多 12 次模型规划，每轮最多 8 次工具调用；MCP 单次超时取连接设置 1–600 秒，平台执行槽与队列限制继续有效。进度通知合并到约 500 ms 一次，保留最近 160 条，每条最多 2 KB；完整 MCP 输出在操作日志中按原有上限保存。网页仅在当前可见页面每秒查询进度，切页/隐藏时停止。

**Demo 边界：** 不连接 GLM 或外部 MCP，不执行宿主厂商命令。含“仿真”或 `simulate` 的任务演示 RC 仿真；含“验证”或 `probe` 演示连接检查；其他任务演示查询项目。都经过真实 MCP 协议，但路由和 EDA 计算明确为离线演示。

## 代码检查、修复与格式化

Code 支持原有 16 种语言；是否能执行检查取决于服务器实际安装并配置的工具。点击右上角“检查工具”，为当前语言设置检查器和格式化器的绝对路径、JSON 参数数组。Verible/Verilator 按钮只填写配置示例，不自动安装软件。

| 用途 | 示例参数 |
| --- | --- |
| Verible 语法/风格检查 | `["{file}"]`，可按项目规则配置；临时文件名为 `design.sv`，检查模块名与文件名时可用 `--rules=-module-filename` 关闭该条与临时命名相关的规则 |
| Verilator 静态检查 | `["--lint-only","--sv","{file}"]`，依赖目录用公司实际绝对路径补充 |
| Verible 格式化 | `["--failsafe_success=false","--lines={startLine}-{endLine}","{file}"]` |
| clang C 语法检查 | `["-fsyntax-only","{file}"]` |

格式化器必须将完整格式化后代码输出到 stdout，stderr 只作诊断；不要配置 `--inplace`。选中行格式化需要 `{startLine}` 与 `{endLine}`，按一开始的行号、两端包含。若工具修改范围外的文本，平台拒绝候选。输出最多 1 MiB，在内存中限制，不将无界 stdout 写入磁盘。

- **检查 / 编译：** 显示工具结果、日志与可识别的文件/行/列；支持常规 gcc/clang/Verible、Verilator、VCS 与 Python 语法诊断格式。点击诊断选择对应代码行；代码已改变或诊断属于依赖文件时提示，不错误定位。
- **检查并 AI 修复：** 先运行检查，失败时将代码、需求和最多 10 KB 的检查日志发送给配置的内网模型，再检查候选。最多修复 1–3 次（最多初检加三次复检），不变候选、无可用检查器或预算耗尽即停止。日志作为证据，不作为模型指令。
- **审阅：** 原文和当前代码不会自动替换。最终候选展示检查是否通过、实际修复次数和每轮日志；检查失败的候选也明确标注，可审阅或丢弃。采用、撤销和另存沿用原有保护。
- **格式化 / 格式化选中行：** 按需启动工具，结果先生成候选，不调用模型、不自动写回文件。没有常驻语言服务器，也没有全盘索引。

检查工具按已配置的 Linux 环境运行，临时源码仅存放在平台数据目录下的短期工作目录，结束后删除。每条检查/格式化命令最长 120 秒，整个检查与修复流程最长 10 分钟，可中止。模型输入仍最多 120 KB；生成完整代码后再复检，不静默截断源代码。

Demo 的检查器只识别明确的 `DEMO_ERROR` 演示标记，修复将其改为 `DEMO_FIXED`；格式化只移除行末空白。演示 PASS 不代表任何编译器、仿真器或功能等价验证通过。正式模式以配置工具实际返回和解析到的错误诊断为准，仍不等于芯片功能、性能或签核通过。

## 参考与验证边界

实现借鉴已有成熟工具的 CLI/检查反馈方式，不引入整个 IDE 或额外常驻进程：

- [Verible 官方 lint 文档](https://chipsalliance.github.io/verible/verilog_lint.html) 与 [formatter 文档](https://chipsalliance.github.io/verible/verilog_format.html)。显式设置 `--failsafe_success=false`，避免默认容错格式化将失败报告为成功。
- [Verilator 官方参数手册](https://verilator.org/guide/latest/exe_verilator.html)，复用 `--lint-only` 配置入口。
- [MCP 官方进度协议](https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/progress)，按请求 token 关联真实通知。现有 Go SDK v1.0.0 需要先初始化 metadata map 再设置 progress token，已在客户端兼容并测试。

本机真实执行 [Verible 官方 v0.0-4296-g0f262651](https://github.com/chipsalliance/verible/releases/tag/v0.0-4296-g0f262651) 的 macOS ARM64 二进制与系统 clang，验证错误、修复后复检、选中行格式化及失败行为。AI 回答由确定性本机合同服务提供；MCP 测试使用官方 SDK 的真实 HTTP/stdio 协议与自建服务。没有使用公司私有设计数据。

这些验证证明平台执行/反馈/保护机制，不证明 GLM 的设计优化质量。CentOS 6.9 实机、商业 EDA、公司 MCP 适配器、厂商许可证和 GLM 工具调用仍需内网验收。Verible 本次仅在开发沙箱用于验证，不随生产包分发；新 CLI 的 CentOS 兼容性须单独验证，不能由平台静态 ELF 兼容性推断。
