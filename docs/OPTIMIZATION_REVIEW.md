# 平台复查与下一阶段建议

2026-09-29。本轮检查对象是 Linux 原生客户端与网页 Demo，申报书没有随本轮产品修复自动改写。

## 本轮已修复

1. 原生客户端工作队列满时，原先只弹出通用错误，没有通知保存请求的失败回调，可能一直显示正在保存。现在恢复保存状态、保留未保存内容，并允许再次保存。
2. 同一项目页切换目录、项目路径、搜索条件和预览文件时，旧响应可能覆盖新结果。现在目录与搜索共用请求身份，文件预览另有请求身份；切换列表会同时清除失效的预览，只有最新请求可以更新界面。
3. 更换搜索词后点击继续搜索，不再复用上一次查询的分页游标。网页版本也按当前查询及项目范围重新开始，不混合两次查询的命中结果。

这是显示及请求生命周期修复，不增加工程副本、不修改持久化结构、不扩大 Agent 权限。原有项目文件、注释、配置和草稿继续使用。修改集以 0.7.0-rc2 候选包单独交付，历史包保留。

建议先把前两项组合为一次迭代：先用固定样例证明模型可靠，再让工程师复用已经验收的任务模板。复杂自主执行与自动调参继续等待真实工具、目标约束和模型能力验证。

上述新增界面范围不是本轮已完成的功能；本轮完成的是前三项可靠性修复。既有长期需求仍保留，新建议不自动当作正式开发承诺。

## 参考方式与取舍

本轮核对了一手文档，借鉴方法而不安装整套现代运行环境，也不宣称下列项目已在 CentOS 6.9 验收。

- [Promptfoo 测试案例](https://www.promptfoo.dev/docs/configuration/test-cases/)支持输入变量、断言、元数据和重复测试。可借鉴“固定数据＋独立判断＋重复运行”的评测组织；优先复用现有测试和后台，不要求目标机安装 Node 服务。
- [Aider Git 集成](https://aider.chat/docs/git.html)展示差异、撤销与版本追踪的交互。借鉴审阅体验；其自动提交行为不照搬到公司工程，避免打包提交工程师原先的修改。
- [Slurm 作业状态](https://slurm.schedmd.com/job_state_codes.html)区分待运行、运行、完成及多类失败原因。可据公司实际队列设计状态映射；进程结束、作业成功和电路指标达标仍须分别判断。

比较 A 整套引入、B 在现有实现增补、C 另建平台后，当前倾向 B：维持 Go 后台和系统 Tk，复用本地数据及权限流程。A 的现代依赖与旧系统兼容、资源占用需要额外验证；C 会重复建设现有能力。本轮未下载新框架、模型或第三方源码，也未引入新的分发许可义务。
