## 2026-10-12 · 0.8.0-rc2 复核与清理

本轮在已有功能上修复两项边界问题，状态格式仍为 Schema 7，没有引入依赖或新业务功能。

- 单位换算：原先只检查指标值溢出，未检查上下限溢出及极小数变成零。现在对已支持单位的数值、min、max 一并校验；超出浮点范围明确拒绝，不把无穷阈值当作无限宽容的规格。CSV 非 UTF-8 和空字符也拒绝。
- 修改集状态：路径不可用、软链接或外部文件修改冲突，原先可能提前把记录改成 checking。现在先验证路径和哈希，确实要写文件时才保存写入意图，已知失败保留上一次状态；原文件继续受冲突保护。真正写入或持久化中断仍可保留 checking，重试会按实际文件哈希恢复，不能据此声称跨文件事务。

针对性测试在修改前复现了上述问题，原始失败记录保留。修复后完整 Go race、vet、网页渲染单测通过；CentOS 6.9 后端 **79 项通过、2 项跳过**（未安装 clang/Verible），Python 2.6/Tk **13 项通过**，实际安装后的原生客户端 **14 组通过**，包括十页打开、文件管理、导入/采用/撤销、波形、计算器落盘、软件环境、插件、设置、模板、指标、回执和窗口/后台生命周期。网页 Demo 的 AI 对话、Code、文件分析入口已实际打开，未观察到控制台错误。

本轮不重跑真实模型推理；上轮两项新流程成功与通用 Agent 历史失败均原样保留，不能把合同服务测试当成模型能力通过。公司 GLM、商业 EDA、GPU、NFS/ACL 仍未现场验收。新版 Demo 启动后 state.json 与 workspace.json.gz 均与更新前字节一致；浏览器页面导航可能正常更新工作区保存版本号。

## 新增功能与操作

| 入口 | 使用方法 | 执行边界 |
| --- | --- | --- |
| AI 对话 → 参数化任务模板 | 选择日志排查、指标整理或脚本修改模板，填写输入文件、关注点与结束条件，预览后填入对话；可保存个人模板 | 选择项目/文件夹后只读取指定输入文件，记录路径和 SHA256；内置模板只读，不执行终端或写文件；可恢复普通对话 |
| 文件分析 → 指标比较 | 导入基线与候选 CSV，核对工况并比较，查看来源行号及导出结果 | 相同指标、corner、电压、温度、condition 才匹配；兼容单位转换，阈值仅取基线；不自动判定设计优劣 |
| Code → AI 多文件修改集 | 指定工程根目录及 1～8 个相对文件路径、输入修改目标；逐文件查看原文、候选和差异，再采用或撤销 | 生成不写原件；采用/撤销检查内容哈希，冲突时拒绝覆盖；逐文件原子写入，不是跨文件事务 |

模板支持文本参数（可填数字/单位）以及 `{{参数名}}` 替换，最多 12 参数、50 个个人模板。预算为 1～12 轮、10～600 秒；当前内置模板是一次指定证据分析，轮数上限不意味着一定使用多轮。指定输入要求普通 UTF-8 文本，最多 100 KB；越界、不存在或不兼容文件会明确报错。

指标 CSV 必填列为 `metric,value,unit,corner,voltage,temperature,condition`，可选 `min,max`。电压填 V、温度填摄氏度数值；condition 例如 ac、dc 或自定义测试条件。每份最多 256 KB、1000 行；缺列、重复工况、无穷值或无效阈值拒绝导入。支持 V/mV/uV/µV、A/mA/uA/nA、W/mW/uW/nW、Hz/kHz/MHz/GHz、s/ms/us/ns/ps、F/pF/nF、ohm/kohm/Mohm、dB、deg、%、1。未知或不兼容单位标记不可比较；dB 不计算百分比；基线为零时不计算相对百分比。候选阈值不能覆盖基线门槛。

多文件每组原文与候选各最多 120 KB，最多保留 20 组；仅保存所选小文件的审阅/撤销文本，不复制工程目录，不创建项目备份或自动 Git 提交。模型返回必须覆盖所选文件且不能增加路径，拒绝软链接越界和平台私有数据。可导出审阅记录；移除记录需确认，移除后无法在平台撤销，工程文件不随记录删除。

## AI 对话与 Code 界面修复

用户反馈的 AI 对话“错码”来自结构化工具输出混入普通答案。网页现在将历史 JSON 和回执折叠，安全渲染标题、列表、行内代码及代码块；Linux 将结构化数据移到原始回执窗口。原始记录没有删除。文件预览和分析拒绝非法 UTF-8，防止二进制被当成文字显示。

实际小模型曾输出“调用 platform_action”的 JSON 文本，却未执行工具。现识别这种伪工具文本并标记未执行/失败，不计为任务成功。模板改为程序读取指定文件并提供带哈希证据，避免依赖小模型猜测文件工具。

Code 原“格式化”改为“预览整份排版”，“格式化选中行”改为“预览选中行排版”。前者忽略选区，后者要求先选代码，只处理涉及的行（不把选区末端下一行误算入）。两者用于缩进与空白整理，不修复电路逻辑；先展示候选/差异，再由用户采用。网页将行末空格显示为差异中的 `·`；原生提供差异窗口，多文件审阅默认选中首个文件，采用或撤销后保留所选文件。没有变化时给出提示。实际格式能力取决于配置的语言工具，Demo 仅做固定空白示例。

保留浅绿色，新增功能用明确的入口与说明；工具栏换行，小窗口 Code 改为单列。原生还修复保存期间再次编辑未立即继续落盘、Python 2.6 无法显示 Unicode 比较占位符的问题。
