## 2. 可靠性证据

- Go：23 个顶层测试项（其中 2 个为子进程测试入口）全部通过，另含错误输入/HTTP/MCP 子测试；`-race` 无竞争报告，核心包语句覆盖率 **74.3%**。覆盖率不是全部正确性的证明；CLI main 的单元覆盖为 0%，其启动/stdio 另有实际进程 smoke 证据。见 docs/validation/go-tests.txt、mcp-stdio.json。
- 静态检查：`go vet`、JavaScript 语法检查、shell/Python 语法检查；依赖模块校验通过，版本及许可证保留。没有完整第三方安全审计结论。
- 浏览器：macOS/Chrome 下通过登录、独立会话/重命名、项目标注/文件、环境卡片、CSV 导入导出、证据问答、Debug 入口、模拟身份、优化、备份及语言持久化；无脚本/网络错误。另检查 AI JSON 草案审阅与 10,000 指标分页。截图及 JSON 记录位于 docs/validation/。
- Linux 构建：Go 1.23.12、CGO_ENABLED=0、linux/amd64/v1，检查为静态 ELF64 x86_64，无动态解释器/动态段。**这是构建与格式检查，不是 Linux 执行测试**。见 linux-elf.json。
- 数据升级：包含项目中文备注/标签、会话、结果、活动任务与优化的旧 schema 样本，迁移前保留原文件快照；重开保留历史；未知新 schema 不覆盖；模拟原子 rename 失败时回滚内存。软件更新与持久数据分目录。

## 3. 数据来源和数值核对

可靠公开输入：ngspice 官方仓库历史固定提交 `032b1c32c4dbad45ff132bcfac1dbecadbd8abb0` 的 `examples/measure/rc-meas-ac.sp`。原文件及 COPYING 保留在 tests/fixtures/ngspice；SHA-256：`896eb7c9cf78f0a3b5635842ac9e4b42312f9928e0eb4d9a60a49f00e4b8068c`。

针对该两级 RC 带通拓扑，用节点方程和独立闭式传递函数核对 41 个频点、生成 82 个幅度/相位指标，最大复数绝对差 **5.93e-17**。数据用于验证导入、单位、来源、显示、导出和 AI 上下文。其来源可靠且推导可重现；**不是运行 ngspice/Spectre 得到的实测结果**。证据与复现脚本：docs/validation/reference-rc.json、scripts/reference_rc.py。

Demo 内置单级 RC 低通公式与上述公开带通电路是不同样例。所有 Demo 页面/回答/导出明确标示。生产包不附带演示 CSV 或预录工程结果；共享业务代码包含显式 demo 分支，生产入口不会启用它。

## 4. 资源实测与部署建议

本地 macOS ARM64 样本：服务空闲 RSS **19.875 MiB**，相隔 10 秒两次 CPU 样本均为 0.0%，累计 CPU 时间未增长。前端本体约 **54.9 KB**（未压缩）。页面一次样本 138 个 DOM 节点、JS heap 约 5.2 MiB；10,000 行指标采用 100 行分页，元数据轮询不携带全部指标或会话。

同次自动化测试的 **Node/Chrome 进程树 RSS 加总约 1,275 MiB（9 进程）**，包括浏览器及测试驱动，RSS 加总可能重复计入共享页，不能视为页面独占内存。它也说明不能只根据前端体积承诺服务器不卡顿。

推荐 Linux 服务＋个人电脑浏览器＋SSH 转发，把浏览器渲染放在个人电脑；不开 Electron、全盘索引或自动后台仿真。若必须在公司服务器桌面运行浏览器，需另测其进程树、空闲/大数据/共享负载，明确可接受预算。本地样本**不代替 CentOS 性能验收**。见 resources.json 与 browser.json。

## 5. 未验证原因与正式版本门槛

| 未验证项 | 原因 | 已准备的验证方法 |
| --- | --- | --- |
| CentOS 6.9 x86_64 实际启动、安装与升级 | 无该系统/虚拟机/远程访问，开发主机为 macOS ARM64 | 每包附 acceptance-linux.sh，收集内核/GLIBC、自检、API、Demo 任务与资源；再执行安装/升级副本验收 |
| GLM 5.3 自由问答、工具调用与答案质量 | 未提供可访问的内网 endpoint/模型标识/凭据；不杜撰地址 | 配置实际接口，先普通问答/历史/取消，再启用 modelTools，核对提效案例 |
| Virtuoso/Spectre 与真实设计 | 无商业安装、许可证、PDK、用户测试平台和版本信息 | 先核对只读身份，再网表/仿真/导出/人工对照，最后取消与有限优化复验 |
| 多种旧浏览器/公司服务器影响 | 当前只具备本机 Chrome；无目标浏览器及共享负载 | 实际浏览器完整流程、空闲/大数据/并发子进程资源与 EDA 影响测试 |
| 仿真任务远端调度/大型团队/NFS 多实例 | 首版是单用户本机前台任务，未接公司调度系统 | 不允许脚本自行脱离进程组；后续单独适配与验收 |
| 节省时间比例或电路性能收益 | 无真实工作流计时基线和 GLM/EDA 实测 | 同一任务/预算对照工程师主动耗时、总耗时、仿真数与许可证占用；不预报“50%”等收益 |

正式版本门槛仍是八组范围的真实目标环境验收、未验证项关闭和用户确认。当前没有借 Demo/合同桩声称生产链路已通过，也没有取消 Virtuoso/Spectre 优先目标。

## 6. 实现取舍与下一步

选择官方 MCP Go SDK＋厂商接口受控适配，而不是引入未经 CentOS 验证的全栈 EDA 桥接。轻量网页和静态 Go 服务减少目标机安装依赖；旧内核同时限制了工具链更新，长期维护成本需持续评估。结果数据以可追溯事实为准，GLM 负责解释与草案，数值结果由仿真/确定性后处理产生。

下一步优先完成一次公司 CentOS 验收和一个固定 Virtuoso/Spectre 测试平台；再用实际 GLM 做结果整理、退化诊断、有限调参三项对照。暂缓项仍保留完整需求，包括工艺迁移、数字/版图专用深度适配、多目标/敏感度、团队知识库与远端会话等，未混入本版完成清单。
