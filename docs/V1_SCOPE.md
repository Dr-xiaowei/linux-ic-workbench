# 第一版范围建议：模拟仿真实验助手

日期：2026-09-21（Asia/Shanghai）。状态：**用户已授权按八组范围开发与验证，并确认 CentOS 6.9 x86_64、模型接口可配置。** 当前交付 0.1.0-rc1 开发候选，生产/Demo 分开；本地实现与证据见 [交付报告](../COMPLETION_REPORT.md)，目标环境未验收。完整需求仍在 [PROJECT.md](../PROJECT.md)，未入选项保留。以下保留范围定义和真实验收门槛。

## 1. 首版定位与特色

围绕模拟工程师的一次实验组织 AI、工具与数据：**选择项目和测试平台 → AI 整理现有结果并定位异常 → 提出有依据的实验/参数建议 → 在限定范围执行仿真 → 自动汇总和比较 → 工程师采纳并生成总结。**

第一版的特色是“能取证、能执行、能比较”的实验助手。平台应展示引用的原始指标/日志、实际动作和运行结果，明确哪些结论已验证、哪些仍是假设。项目和软件管理服务于这条流程，不单独扩成庞大的管理系统。

以一个用户指定的模拟模块和固定测试平台贯穿首版，例如运放或 LDO，具体由真实工作选择。**优先验证 Virtuoso/Spectre 链路已确认**，实际 ADE/Spectre 版本和受支持脚本需核实；遇到阻碍记录原因并讨论，不自行换成其他仿真器或用独立网表运行代替 Virtuoso 联通验收。

首版有两个并列入口：**AI 对话**用于内网直接提问，无需绑定项目；**项目实验助手**用于结合工程材料分析和执行。用户可以先正常问答，确需处理工程时再选择项目与上下文。

若 GLM 暂不能稳定产生工具调用或结构化输出，需解决接入或调整方案后再确认交付能力；不能用任意模型文本直接拼接执行命令。若真实 EDA 通路未跑通，只能交付对应 Demo/开发候选，不把文件上传聊天界面当作这一首版的正式完成。

## 3. 独立问答与三个可测量的实验场景

普通问答验收：在未选择项目、EDA 未启动且 MCP 未连接时，可直接向真实 GLM 提问并多轮追问；重启后找回会话，中英文入口可用，模型超时明确反馈。Demo 中对应回答如为预录必须标明，不能伪装自由问答已接入模型。

| 场景 | 工程师发起的任务示例 | 实际产出 | 提效验收建议 |
| --- | --- | --- | --- |
| 整理一批结果 | “汇总这批 PVT 的增益、带宽、相位裕度，找出未达标和没算出的点。” | 带工况/单位/来源的指标表、失败清单、CSV 与总结 | 与用户现有手工或脚本流程比较；建议目标为主动整理时间减少至少 50%，关键指标与人工核对一致。该比例是待确认目标，尚未实测 |
| 排查一次退化 | “比较这两次仿真，解释相位裕度为何下降，下一步验证什么？” | 差异、来源、分开的事实/假设、验证实验草案 | 用已知结论/待验证证据的案例，记录定位时间、有效建议和错误建议；允许证据不足，不用回答篇幅当收益 |
| 执行一次调参 | “在这些参数范围与预算内改善相位裕度，同时满足增益和功耗约束。” | 每轮参数/状态/指标、基线和可行候选对比、复验记录、采纳建议 | 记录省下的人工改参/提交/整理步骤与主动操作时间；比较相同预算与条件，不承诺每个电路均改善或全局最优 |

分别报告工程师主动耗时、端到端耗时、仿真次数及许可证/计算占用。仿真本身耗时不能计成 AI 节省的时间；即使任务无人值守，也不能把增加的计算预算隐去。回归样本同时包含成功、失败、缺失单位/工况、不收敛和模型不可用场景。

## 4. 正式版与 Demo 的交付区别

2026-09-23 更新：Demo 改为网页预览，不再交付独立安装包；此前独立包安排被用户最新指令替代，配置/数据/模拟标识隔离要求继续有效。

**两者共用业务实现，入口、配置、持久数据和交付物分开；开发候选未通过验收前不称正式版。** 对应交付分别位于 release/ 与 demo/，共享业务代码。

| 维度 | 正式版 | Demo |
| --- | --- | --- |
| 用途 | 在公司内网处理真实项目与受控 EDA 任务 | 演示/培训/界面验收，覆盖已确认的首版全部功能 |
| 模型 | 实际 GLM 服务，记录真实状态与错误 | 默认可离线使用，预录回答醒目标记；经明确配置也可演示真实内网 GLM，不能伪装已连接 |
| EDA 执行 | 已在目标 Linux、授权和版本组合上验收的执行适配器 | 受控模拟执行器/回放，明确标示非真实 EDA；运行进度、异常与指标来源均有标识 |
| 数据 | 用户项目、真实结果与独立持久化存储 | 合成/获准脱敏样例，独立配置、缓存、日志、数据库与产物；不读取正式凭据或真实工程 |
| 默认行为 | 正常首次启动不注入演示数据 | 固定 Demo 标识和独立入口，禁止误连正式数据目录；重置只清除确认的 Demo 数据 |
| 开发与打包 | 正式配置档及单独安装/启动入口，交付到 release/ | Demo 配置档及单独入口、样例数据，交付到 demo/；生产包不混入预录结果或真实私有资料 |
| 验收 | 真实 GLM、EDA、数值正确性、权限、取消/恢复、升级保留及 Linux 性能 | 每个首版功能有可操作样例，含失败/预算耗尽/断线情景；覆盖功能不等于真实 EDA 验收 |

运行时先校验交付模式和数据根目录，禁止 Demo/正式实例共用持久数据目录，含软链接或路径别名指向同一目录的情况；不能靠同一个设置开关任意切换并沿用数据。Demo 导出材料保留样例/模拟标识。真实资料如需成为演示输入，应经过独立脱敏和显式导入流程，不能从正式数据库直接复制。

## 5. 第一版暂缓的范围

- 全面工艺迁移、原理图/版图自动修改、全公司 PDK/工具适配。
- VCS/PrimeTime/Calibre 等专用报告深度解析与专属自动流程；数字 DE/版图人员可使用项目、环境卡片和文本助手，但不宣称已完成其专业适配。
- 高级多目标优化、自动拓扑探索、完整 MC/后仿优化、统计重要性/敏感度、分级筛选策略。
- 全项目变更影响图、正式评审例外审批、机构远程桌面门户、团队知识权限体系。
- 通用波形引擎、全盘索引、自动整理全部个人文件。

这些仍属于完整需求或已确认方向，暂缓只表示不进入首版交付。首版保留可靠版本/来源、单位、预算和数据迁移基础，便于后续扩展；不能把缺失能力展示为已完成。

## 6. 方案、依赖与验收状态

MCP 实现顺序为：**GitHub 原仓库调研与成熟度/许可核查 → 固定版本并比较复用方案 → 按获确认路线隔离验证 → Virtuoso/Spectre 最小链路 → 接入平台。** 不因仓库名称包含 MCP/Virtuoso 就直接安装执行。实际采用官方 MCP Go SDK v1.0.0（Go 1.23），适配厂商 OCEAN/SKILL 接口与公司已有脚本；未找到可直接证明 CentOS 6.9 与公司版本兼容的成熟全栈控制器。SkillBridge、virtuoso-bridge-lite、virtuoso-cli 的评估和未采用理由见 [REFERENCES.md](../REFERENCES.md)。若没有满足条件的完整桥接，优先比较成熟协议组件加厂商接口/既有脚本的受控适配，并明确新增开发责任。

复用路线继续沿用已有 A/B/C 比较：A 单独使用现成工具可验证局部能力，但不能交付上述统一流程；B 以受控适配器连接既有 EDA/环境脚本，并按需复用成熟优化组件，作为首选评估方向；C 自建业务层保留为备选，成本在于数据、运行恢复和 UI。当前采取 B 路线的受控适配，加自有业务层；未 fork Harness、引入 Optuna/Lmod 或部署其他框架。

开发前先明确四组事实：① 一个目标模块、测试平台、仿真器/ADE 版本与一份获准样例；② Linux/远程访问方式和现有启动脚本；③ GLM 的接口及工具调用/结构化输出能力；④ 单次试验预算、允许修改范围与 UI 资源上限。不需要提供明文凭据。这些事实用来确定适配和验收，不要求现在把所有远期需求决定完。

首版完成门槛：上述八组范围按确认边界可用，三个场景通过真实环境验收，Demo 全功能覆盖且数据隔离成立，中英文/性能/升级回归通过，再由用户确认正式发布。若关键接口受阻，应明确受阻项并讨论调整范围，不默默取消真实仿真闭环。

本轮已实现八组功能并交付候选，真实 GLM/EDA、CentOS 6.9 和提效收益仍待现场验收；不宣称达到正式发布门槛。不重新启用历史 MVP-01～06，不承诺未经实测的提效比例。
