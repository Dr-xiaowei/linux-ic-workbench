# 0.5.0-rc3 · 多用户、终端启动与可靠性复验

日期：2026-09-26。沿用上一轮保留的 QEMU CentOS 6.9 x86_64、Linux 2.6.32、glibc 2.12 与本地小模型，没有重新下载系统或模型。真实商业 EDA 调用仍按用户要求排除。平台数据仅登记项目路径与配置，不复制工程。

## 本轮修改

- **终端启动：** 安装后运行 `~/.local/bin/ic-workbench`，在 PATH 中时可直接用 `ic-workbench`。`--status` 显示本人正在运行的服务；Ctrl+C 正常停止。同一数据目录重复启动复用现有服务。命令兼容 sh/bash/csh/tcsh，不改全局启动脚本。
- **独立实例：** 默认由操作系统分配回环空闲端口；旧配置的固定端口被占用时可回退。显式 `--listen` 保持指定端口，冲突时明确失败。各用户有独立 HOME 配置、数据和随机令牌，程序本身可只读共享。
- **访问边界：** 生产目录核验当前 UID、0700、真实目录和上级访问边界；平台文件核验 0600、所有者、常规文件及硬链接数量。拒绝错误共享数据和链接替换；已有数据不清理，已有共享目录权限不擅自修改。
- **可靠写入：** 初次配置创建加锁并原子发布；保存失败保留此前磁盘和内存值；重命名后同步失败属于不确定持久化，报告错误、停止进一步写入，待检查磁盘后重启。异常退出后仅清理本程序私有临时写入文件。
- **关闭及恢复：** 停止时取消启动验证、模型和后台任务，停止接收新 API 请求并等待当前请求结束。失效网页令牌返回重新登录表单，替换令牌时清除上一实例的临时 Agent 引用。
- **升级与 MCP：** 安装先复制到临时目录并复核校验和，再发布版本、切换入口；不覆盖无关的同名命令。MCP CLI 自动发现本人实例的动态端口和令牌，默认仍为只读工具。

Schema 保持 6，草稿 Schema 保持 1。没有新增数据库、索引、常驻桌面框架或工程备份。

| 检查 | 结果与证据 |
| --- | --- |
| 完整宿主 race 回归 | 57 个顶层测试通过、0 跳过，包括真实宿主 Verible/clang、模型/MCP 合同和新增异常测试；[原始记录](validation/reliability-rc3/go-race.txt) |
| 完整 CentOS 回归 | 55 个顶层测试通过；2 项因该最小虚机没有 clang/Verible 跳过。包含真实 csh、Python 2.6、进程取消、存储、协议合同；[原始记录](validation/reliability-rc3/go-centos.txt) |

| 跨用户拒绝 | 互换令牌得到 401；另一个用户读取数据、误指定共享数据、登记无权限项目或终止另一 UID 的进程均拒绝 |

| 真磁盘写满 | 专用 2 MiB tmpfs 实际返回 ENOSPC；记录与草稿写入报错，旧字节保持，释放空间后恢复保存 |
| 损坏与权限 | 损坏 JSON/gzip、额外 JSON 配置、不安全目录、文件软/硬链接拒绝；不自动清库或恢复默认值；目录 fsync 失败通过可控故障注入测试 |
| 短时请求负载 | 双用户共 620 次 API 请求，响应与账户归属正确 |
| 三分钟持续负载 | 180.23 秒、2,624 次读取/计算请求，全部正确；两实例 RSS 约 10–14 MiB，采样文件描述符均为 8；[资源曲线](validation/reliability-rc3/soak.json) |

上述 12 组 CentOS 真实 UID/故障验证的完整凭证见 [multiuser-faults.json](validation/reliability-rc3/multiuser-faults.json)。测试源码在 `tests/linux_reliability_guest.py` 与 `tests/linux_reliability_soak.py`，只用于专用虚机。首次测试载荷曾继承宿主文件权限、Python 2.6 测试比较曾混用 Unicode；修正测试准备和编码后重新执行全部检查，没有放宽产品权限规则。

浏览器复验覆盖独立 SSH 端口下的两个用户、过期令牌登录、项目文件、草稿、十页/双语/窄屏；复用真实 Qwen2.5-Coder 1.5B 验证问答、原页分析和 Code 修改，并用 CentOS Python 2.6 检查候选代码。最终浏览器与安装凭证归档在同目录；包内报告对应的二进制 SHA-256 可与 ELF 检查交叉核对。

**交付后补验全部通过：** [生产浏览器 5 组](validation/reliability-rc3/browser.json)、[最终包真实安装与重启](validation/reliability-rc3/installed-package.json)、[Demo 无损更新](validation/reliability-rc3/demo-upgrade.json)。最终包 158 个文件校验通过，11,097,482 字节；SHA-256 为 `5da4f9c66ecb2879698072bb0370d9256bcfed3f5cf422d7fc04e3aada14f643`。rc2 的配置/主记录/草稿三份文件逐字节保留；四种 shell 均可调用入口，SIGINT 停止及重新启动通过。另测同时安装同一版本，只有一个成功发布，带空格的路径与最终校验和正确。安装后产生的凭证保存在工作区，未回写压缩包，以保持已实际安装验证的包哈希。

## 使用及边界

完整命令、SSH 转发与升级方法见 [部署说明](DEPLOYMENT.md)。旧个人目录若权限不符合要求，启动会报出路径；确认是个人专用目录后修正权限，或使用真正的私有数据目录，不要对公司共享工程整体 chmod。项目目录依旧按 Linux 本身权限访问，可以是公司共享项目。

这里验证的是不同普通 Linux UID 的独立实例；同一个共享 Linux 账号或 root 管理员不属于个人隔离边界。没有对公司 NFS/ACL、物理断电、真实 NVIDIA、GLM 5.3、商业 EDA/PDK/许可证进行现场验证。CentOS 内的 clang/Verible 专用测试未运行，宿主通过不能替代其 Linux 版本兼容性。

三分钟负载不是数日运行或大型工程压力证明；QEMU TCG 的 CPU 时延不代表真实服务器。小模型的代码语义和芯片设计正确性仍需工程验证。上一轮的全部非 EDA 功能、小模型输出限制与来源记录见 [完整 QEMU 报告](LINUX_QEMU_VALIDATION.md)。

验证环境文件继续保留。测试服务可正常停止以释放 CPU/内存；镜像、工具、模型和虚拟磁盘均须经用户明确确认后才删除。
