# 本地数据、升级与 Code 修改

适用 0.5.0-rc3。个人数据保存在工作台服务所在机器，不依赖某个浏览器的缓存。生产与 Demo 数据目录隔离。远端 Linux 经 SSH 转发访问时，“本地”指该 Linux 账户；电脑上的浏览器关闭后，已保存数据仍在 Linux。不同 Linux UID 使用各自私有的 0700 配置/数据目录和 0600 平台文件；共用只读程序不共用数据库。终端入口、动态端口与旧目录权限处理见 [部署说明](DEPLOYMENT.md)。

## 保存什么、保存在哪里

| 内容 | 默认位置 / 行为 |
| --- | --- |
| 安装文件 | `~/.local/opt/ic-workbench/releases/<version>-production/`，升级创建新版本目录 |
| 启动配置 | `~/.config/ic-workbench/production/config.json`，只在首次启动不存在时初始化；`ICW_CONFIG_DIR` 可改目录 |
| 平台数据 | `~/.local/share/ic-workbench/production/`，`--data` 或配置 `dataDir` 可改位置；升级需沿用同一位置 |
| 已保存项目/文件备注、标签、软件版本环境、模型偏好、插件、MCP、检查工具、对话、执行记录 | `state.json`，保存即原子落盘；紧凑 JSON，64 MiB 上限 |
| Code 原文/当前草稿/待审候选/替换历史，分析文件文本/答案/记录，计算器变量/结果，未发送的问题和对话范围 | `workspace.json.gz`，约 900 ms 停止编辑后压缩自动保存；未压缩 JSON 上限 12 MiB |
| 升级前原始记录 | `pre-migration-*.json`，格式迁移前创建，不删除 |
| 手动备份 | 已取消；公司统一负责工程备份。旧 `backup-*` 文件保留，不再生成 |

网页 Demo 默认在开发目录 `runtime-data/web-demo/`。安装/升级脚本不会清理数据、外部工程或配置。不得将工作数据放在某个版本的安装目录里面，否则人工删除该目录也会删除自己的数据。

模型密钥仍从设置指定的环境变量读取，MCP 认证同理；密钥值不回传网页，也不保存在普通草稿。启动配置、外部环境脚本、用户本来的 shell 凭据配置仍需自行保存在账户的固定目录并备份，不随安装包替换。项目只登记路径，不搬移或复制源工程。平台不提供工程备份；工程、厂商输出、外部脚本及密钥按公司备份方案管理。

## 自动保存与占用

顶栏显示“待保存 / 正在本地保存 / 已保存在本机 / 保存失败”。点击可立即保存。关闭页面前等到“已保存在本机”；未落盘时浏览器会尝试提醒，强制杀浏览器/断电仍可能丢失最后不足一秒的编辑。已落盘文件采用同目录临时写入、fsync 与原子重命名。NFS、磁盘故障和断电仍需在实际环境检验。

多标签页同时修改不会静默覆盖：过期 revision 被拒绝。在失败提示中先“导出本页草稿”，再“重新加载本机版本”；导出的 JSON 保留当前未保存内容，可直接提取代码文本或其他字段恢复。不要用旧页持续覆盖新的工作。

设置页显示记录、压缩草稿、旧备份、其他运行文件的字节数，扫描设置 2 秒 / 20,000 项的检查预算且不追踪链接（底层文件系统 I/O 不保证严格超时）；受限时明确显示不完整。不会复制工程目录，不保存波形重复绘图点，不为每次自动保存新建历史文件。只有导入替换/重新生成/显式恢复等操作保留 Code 历史；每种语言一份当前草稿，最多 200 条历史和 200 条分析记录，同时受 12 MiB 总上限约束。满额时拒绝新保存，原有磁盘数据不变；可导出需要的记录，再在草稿历史或分析记录中明确删除不再需要的项目。

旧备份、对话和运行文件不会自动删除，所以整体占用仍随使用增长；压缩并不保证任意仿真数据都很小。显示的是文件逻辑字节数，文件系统分配块可能更大。没有后台全文索引、浏览器框架或新增常驻进程。

## 导入并修改代码

1. 进入 Code 平台，导入 UTF-8 文本（最大 1 MiB，拒绝二进制和无效 UTF-8）。扩展名自动识别 16 种语言；额外接受 `.vh`、`.svh`、`.vhdl`、`.cir`、`.spice`、`.ils`、`.bash`、`.h`、`.hpp`、`.cc`、`.cxx`。
2. 在左侧写修改目标、接口/行为约束；右侧是当前代码。点击“AI 优化当前代码”。AI 输入上限 120 KB，超限会提示，不能静默截断源代码。
3. 下方并列显示送给 AI 的代码和可编辑候选，以及修改说明。正式模式调用配置的内网模型；不执行代码、不写源文件。Demo 只做可复现的行末空白/换行整理，明确没有优化电路逻辑。
4. 点击“采用修改”后更新编辑区，可撤销最近一次采用。若当前代码在等待期间又被编辑，采用会拒绝，需重新请求建议。原文始终可展开、导出。
5. 用配置的检查工具验证，再“导出文件”或“另存为”。另存使用排他创建，已有目标文件不会覆盖。导入其他同语言文件之前，当前草稿进入本地历史。

检查修复闭环、诊断定位和格式化用法见 [新功能指南](EDA_TASKS_AND_CODE_CHECKS.md)。EDA 对话草稿、最新任务状态和检查/修复回执同样在本地保存。

AI 返回合法代码不等于编译、综合、仿真、功耗、时序或模拟性能通过。本轮没有真实 GLM / 厂商工具验收。

## 升级与历史恢复边界

升级直接沿用数据目录，无需导入导出。修改启动配置后依然使用原 `config.json`。迁移前保留旧状态快照，后续程序不认识的新 schema 会被拒绝，不强制降级写入。

恢复时先停止平台并完整保留现有目录，在**全新的空目录**操作，避免覆盖升级后新数据。仅适用于已经存在的旧版文件：0.4 备份解压后是 `{format, state, workspace}`；将 `state` 写成 `state.json`，将 `workspace` JSON 以 gzip 写成 `workspace.json.gz`，写入与 state.mode 一致的 `MODE`，文件权限 0600、目录 0700，再使用匹配版本的 `--data <新目录>` 核查。旧版备份仅包含 state，没有此前未保存的网页草稿。完整灾难恢复还需单独保存原数据目录中的运行产物、用户配置和工程目录。
